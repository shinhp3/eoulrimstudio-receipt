[1] 이 저장소 앱이 하는 일
--------------------------------------------------------------------------------
- 브라우저에서 견적서를 작성하고, Cloudflare Worker(API)를 통해 JSON 견적을
  서버에 저장·목록·삭제·불러오기 한다.
- 단일 페이지(index.html) 안에 두 영역이 있다.
  (1) 작성 탭: #app 에 마운트되는 견적 에디터 + 미리보기 (app.js / renderForm)
  (2) 대시보드 탭: 저장된 견적 목록 카드 UI + 검색/정렬 (정적 마크업은
      index.html, 목록 내용은 app.js가 #server-table-wrap 에 주입)


[2] 사용자에게 보이는 화면 구조 (index.html)
--------------------------------------------------------------------------------
- 상단 헤더(.app-shell-bar)
  - 탭 역할 버튼 두 개
    - id="tab-write-btn"   data-main-tab="write"    → 작성
    - id="tab-dash-btn"    data-main-tab="dashboard" → 대시보드
- 패널 전환
  - id="panel-write"   class에 tab-panel-active / tab-panel-hidden 토글
    - 자식 #app → 견적 앱 전체가 여기 렌더링됨
  - id="panel-dashboard"
    - .dashboard-page.dashboard-page-embedded
    - 제목: .dashboard-title "대시보드", 리드: .dashboard-lead "저장 목록"
    - 버튼: #btn-new-quote (새 견적 작성), #btn-refresh-server (서버 목록 새로고침)
    - 상태 메시지: #dashboard-status.dashboard-global-status
    - 섹션: .dashboard-section.panel

      - 목록 컨테이너: #server-table-wrap.dashboard-table-wrap  ← JS가 테이블 HTML 삽입


[3] 반드시 필요한 전역 설정 (Worker API 베이스 URL)
--------------------------------------------------------------------------------
- 스크립트 로드 **전에** 다음이 설정되어 있어야 한다.
    window.__EOULRIM_UPLOAD_API__ = '<Worker Origin, 슬래시 없이 또는 있어도 됨>';
- quotes-shared.js 가 이 값을 읽어 CLOUD_API_BASE 로 정규화한다.
- 현재 index.html 예시 값 (배포 환경에 맞게 교체 가능):
    https://eoulrimstudio-upload.eoulrimstudio.workers.dev
- 비어 있으면: 대시보드는 안내 문구를 띄우고, 저장/목록 API 호출이 실패한다.


[4] Worker REST API (대시보드·작성 탭이 공통 사용)
--------------------------------------------------------------------------------
- GET  /quotes              → 목록. 응답 JSON의 items 배열. 각 항목에 name(파일명) 등.
- GET  /quotes/{fileName}   → 견적 JSON 본문 (URL 인코딩된 파일명)
- PUT  /quotes/{fileName}   → 저장(작성 탭 저장 버튼 플로우)
- DELETE /quotes/{fileName}→ 대시보드 카드에서 삭제
- GET  /quotes/next-dispatch → 발송번호 자동 채번 (작성 탭)
- 구현 참고: worker.js , workers/upload/src/index.js (배포본과 동기 여부 확인)

통합 대시보드가 **다른 오리진**(별도 도메인)에서 이 앱을 iframe으로 띄우면,
Worker 쪽 CORS 설정이 해당 오리진을 허용하는지 확인해야 한다.


[5] 라우팅·딥링크 (통합 사이트에서 링크 걸 때 유용)
--------------------------------------------------------------------------------
- 해시
    index.html#dashboard  → 부팅 시 대시보드 탭 선택 (bootQuoteEditor 마지막 줄 근처)
    해시 없음             → 기본 작성 탭
- 쿼리 (직접 특정 견적 편집 진입)
    index.html?cloud=<URL인코딩된 파일명.json>
  → 해당 파일 GET 후 작성 탭으로 전환, 에디터에 로드. 이후 URL에서 쿼리는
    replaceState 로 정리됨(app.js bootQuoteEditor).

통합 대시보드에서 “견적 앱으로 가기” 링크 예:
    https://<견적앱 호스트>/index.html#dashboard
    https://<견적앱 호스트>/index.html?cloud=my_quote.json


[6] 탭 전환 로직 (app.js)
--------------------------------------------------------------------------------
- 함수: switchMainTab('write' | 'dashboard')
- 대시보드로 올 때: persistDraftFromDom() 후 패널 클래스 토글, 그리고
  fetchDashboardServerRows() 호출해 목록 갱신.
- 작성 탭으로 올 때: 미리보기 레이아웃 fitQuotePreview 재실행.


[7] 저장 목록(대시보드) 데이터 플로우 (app.js)
--------------------------------------------------------------------------------
- fetchDashboardServerRows({ force })
  - 캐시·중복 요청 방지: dashboardQuotesInvalidateNext, dashboardFetchGen
  - listCloudQuotes() 로 목록 → 각 파일에 대해 getCloudQuote() 최대 6개 동시
    (mapPool, 메모리 보호)
  - 성공 시 dashboardQuotesMetasCache 에 메타 배열 저장 후
    renderDashboardQuotesTable(wrap, metas) 호출
- renderDashboardQuotesTable
  - 검색: dashboardDispatchFilterRaw (저장이름·발송번호·파일명 등 소문자 부분일치)
  - 정렬: dashboardSortOrder + sortDashboardMetas
  - 각 행은 테이블의 넓은 셀 안에 “카드” 한 장 구조:
      table.dashboard-table.dashboard-table-pro
      tbody tr.dashboard-row-quote > td.dashboard-cell-card > .dashboard-quote-card
    상단(.dashboard-floor-top): 요약 + 상태 pill + 날짜 + 수정/삭제 아이콘 버튼
    하단: 본문 로드 실패 시 경고, 성공 시 details 로 품목 표 접기/펼치기

[9] NEW 배지 동작 (방금 저장한 항목 표시)
--------------------------------------------------------------------------------
- 상수: app.js 의 DASH_NEW_BADGE_MS = 5 * 60 * 1000  (5분)
- sessionStorage 키: eoulrim-dash-new-quote  값 JSON { fileName, ts }
- 저장 성공 시 markDashboardJustSaved(fileName) 로 한 번만 기록(덮어쓰기).
- 목록 렌더 시 파일명이 일치하고 (지금-ts) < DASH_NEW_BADGE_MS 일 때만
  dashNewBadgeHtml 이 NEW 마크업 반환.


[10] 통합 대시보드에 넣을 때 권장 패턴
--------------------------------------------------------------------------------
A) iframe 임베드
   - src 예: .../index.html#dashboard
   - 높이: 카드 목록이 길어지므로 세로 스크롤 가능한 컨테이너 권장.
   - __EOULRIM_UPLOAD_API__ 는 이미 index.html 에 박혀 있으면 추가 작업 없음.

B) 새 탭 / 링크만 제공
   - 운영 호스트의 index.html#dashboard 또는 ?cloud=...

C) 통합 사이트가 “목록만” 직접 그리고 편집은 이 앱으로 넘기려면
   - 최소한 GET /quotes, GET /quotes/{name} 스펙을 맞추거나,
   - 위 딥링크 ?cloud=파일명 규칙으로 이 앱 작성 탭을 연다.

※ 현재 코드베이스에는 postMessage 브리지가 없음. iframe 부모↔자식 제어가
   필요하면 별도 구현이 필요하다.


[11] 관련 파일 빠른 목록
--------------------------------------------------------------------------------
- index.html          : 셸 레이아웃, 탭, 대시보드 정적 골격, __EOULRIM_UPLOAD_API__
- dashboard.html      : index.html 로 리다이렉트만 함 (실사용 진입은 보통 index.html)
- app.js              : 탭 init, 대시보드 fetch/render, 작성 마운트(bootQuoteEditor)
- quotes-shared.js    : CLOUD_API_BASE, list/get/put/delete Cloud 헬퍼, payload 변환
- styles.css          : .dashboard-* 스타일 대부분


[12] 다른 AI에게 줄 한 줄 요약
--------------------------------------------------------------------------------
“단일 index.html 안에서 작성(#app)과 대시보드(#server-table-wrap) 탭을 전환하고,
 window.__EOULRIM_UPLOAD_API__ Worker로 GET/PUT/DELETE /quotes 를 쓴다.
 통합 사이트에서는 iframe 또는 링크로 index.html#dashboard 또는 ?cloud=파일명 을
 연결하면 된다.”
